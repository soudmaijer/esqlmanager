
eSQLManager changelog
---------------------

05-10-2026: Modernisation (Maven, Java 25, PostgreSQL support)

- Build: Maven with the Maven wrapper, standard src/main/java and src/main/resources layout, Java 25, UTF-8 sources.
  The old dist and lib folders are gone, JDBC drivers (MySQL, PostgreSQL, SQL Server, Oracle) come from Maven Central.
- Packages: merged esql and nl.errorsoft into nl.errorsoft.esql, the database designer lives under it as dbcreator.
- Runtime files (conf, credits) are grouped in runtime/, passwords are no longer part of the committed profiles.
- Dialect layer: everything that differs per database (quoting, literals, DDL, paging, switching database,
  maintenance, export, process list, status, users) is decided by a Dialect. Callers no longer check the server type.
- PostgreSQL support with the right defaults (port 5432, user postgres). All features work on PostgreSQL and MySQL:
  create/modify/drop tables, columns and indexes, import and export as SQL, database designer, user manager
  (roles and privileges), process list, server status and variables, table maintenance (VACUUM, ANALYZE).
- User manager rebuilt: a UserAdmin per dialect and a new window. It works on MySQL 8, which the old one did not
  (it wrote into the mysql.user table).
- Generated SQL: values are escaped per database and names are quoted by the dialect. The WHERE clause that finds a
  row for editing, deleting and uploading is built in one place. An empty cell is stored as NULL, not as the text "null".
- Paging orders by the primary key, so rows no longer move after an update on PostgreSQL.
- Export/import: one code path, UTF-8, NULL values, auto numbering continues after an import on PostgreSQL.
- Logging with Log4j 2 instead of System.out, with connection details and queries in the output panel.
- Look and feel: FlatLaf instead of the native macOS look, which made resizing very slow. Resizing the window and the
  output panel is fast, the output panel scales with its panel, has a vertical scrollbar and no longer wraps lines.
- Status bar shows the server, the account and the last action (rows loaded, time taken) instead of a copyright text.
- Data grids show subtle grid lines and size their columns to the content.
- Removed: license and registration checks, the auto-updater and its dialog, the dynamic class loader, old unused
  files and commented out code.
- Cleaned up: resources are closed with try-with-resources, deprecated API calls replaced.
- Tests: JUnit and Testcontainers run the same scenarios against PostgreSQL 17 and MySQL 8.
- Documentation: README with a feature list per database and a screenshot, CLAUDE.md with the design decisions.
- Architecture: packages per feature (table, database, importexport, blob, user, designer, query, connection, app), each with
  controller, service and repository layers. SQL only runs in repositories, which ask the Dialect. The domain classes are plain data.
- ApplicationContext resolves the image loader, settings and the ConnectionContext of every open connection. A ConnectionContext wires the
  repositories and services of one connection once, controllers no longer create them.
- Errors: one ErrorHandler logs an error once and shows one message, services and repositories no longer swallow exceptions.
- Appearance: the look and feel is a preference (Settings > Preferences): follow the system, light, dark or native. On macOS the Mac themes of
  FlatLaf are used, with the menu in the screen menu bar and the title bar following the system.
- Icons: the GIF icons (also the red and green status light) are replaced by vector icons from Lucide (ISC license, in resources/icons/svg). They scale sharply on high resolution
  screens and follow the colours of the light and dark theme.
- Output panel: log lines are shown exactly as written (the first line was indented one space less than the others), and the text colour
  follows the theme.
- Query editor: RSyntaxTextArea replaces the home-made highlighter (SQL highlighting, line numbers, undo and redo), its colours
  follow the light and dark theme. The output panel is plain text in a monospaced font, syntax.xml is gone.
- Status bar: the status light is in front of the message ("Ready..."), the connection info is centred.
- Java 25: records, pattern matching, switch expressions, text blocks, lambdas and virtual threads for background work. Resources are closed
  with try-with-resources (DatabaseConnection included), Observable is replaced by ProgressListener, the PRO/LE distinction is gone.
- Code style: Spotless formats the sources (tabs, 160 columns, LF), .editorconfig added, the build checks the formatting.

build #64 - RC3

- Added a VM version check, VM`s lower than 1.4 won`t be accepted and an error is thrown.
- The auto-updater now knows what file (le or pro) to get from the update server.
- Fixed the build.xml script for ant. 
- Build in checks for program parts that only work on MySQL.
- Fixed a bug while receiving indexes on MSSQLServer.

build #63 - RC2

- New directory structure for the application.
- Fixed a bug in loading the classpath libraries, use a URI for filepaths now!
- Added LicenseKey tool!
- Added VIEW`s to table overview.
- Export data ignores binary files from now on.
- Created a DynamicLoader class which add jar libraries to the classpath at runtime. By default all the jars in the lib dir are included in the classpath now, this solves the third-party jdbc driver problems.
- Fixed a little bug in the ConnectionProfileUI, when deleting the last profile the textfields where never cleared.
- The main window now uses as default size the maximumscreenbounds, no more resizing of the main window when starting eSQLManager.
- Fixed bug: advanced table data edit opened if a cell of a new row was selected.
- Added a new splashscreen, the splash class now adds all information to the splashscreen.
- Added documentation to the help files.
- FieldProperties and create table are now consistent with each other. Changed the signed in FieldProperties to unsigned. By default all numbers are signed, see documentation in the help.
- Fixed problems with error handling in Import + Export interfaces. When import or export fails during the process a message is displayed why it failed.
- Smashed a bug in the indexes interface, unique was never set if an index is unique, fulltext can`t be set via JDBC driver, need to find a solution for this problem.
- Added status messages to inform the user what esqlmanager is doing.
- Drop table and drop database now remove the data tab in the ConnectionWindowUI.
- Edit table now works for all table properties (name, comment, type) except for the tablecolumns.
- Create table doesn`t allow indexes or keys to be defined anymore, need to create a table first and then add indexes with the indexes manager.

build #61 - beta

- Finished the index manager, eSQLManager Pro is now beta status! Only bugs will be fixed until the 1.0 release.
- dbcreator uses esql.domain.DataType, removed esqlcreator_sql.xml
- Removed confirmation message from connectionwindow when no connection to a server could be made.
- Syntax documents and query window now use the syntax.xml for sql keywords.
- Removed more old Java files which were no longer needed.
- Changed the datatypes.xml file and improved the working of the loading of the datatypes in the ServerType class.
- Changed the connectionprofile startup sequence, now first the profiles are loaded before showing them.
- Implemented the new DatabaseDriver class. All JDBC driver settings can now be managed with an UI. The driver.xml file contains al settings needed.
