
eSQLManager changelog
---------------------

05-10-2026: Database work off the event thread in controllers and dialogs

- Opening table data and paging through it, the Indexes and Edit table tabs and table maintenance (optimize, analyze,
  check, repair) load in the background: the window stays responsive and the status light shows what is loading.
- The user manager loads databases, tables, users and privileges and applies changes in the background, with its
  controls disabled meanwhile.
- Generate model checks and generates a copy of the model taken when the dialog opens; a note linked to a database
  no longer breaks the generation.

05-10-2026: Wrong database, schema and statement handling

- Dropping, emptying, renaming and changing a table, its columns or its comment, and table maintenance, run in the
  table's own database, also after a query tab moved the shared connection to another database.
- The query tab shows the rows of every statement that returns them (WITH ... SELECT, EXPLAIN, VALUES, TABLE t, a
  query after a comment or in parentheses), not only SELECT and SHOW. Switching database in the query tab is written
  the server's way: USE db on MySQL, \connect db or \c db on PostgreSQL.
- A query that fails no longer leaves its statement open on the server.
- Open in designer leaves out a foreign key on a table of another schema, also when the schema read has a table with
  the same name.
- The user manager asks to revoke exactly the privileges that Apply then revokes (the privileges are read once).
- Export and import refuse a node that is not a database, schema or table instead of exporting nothing.
- Saving cell data to a file adds ".txt" only when the name has no extension (notes.txt no longer becomes
  notes.txt.txt).

05-10-2026: Actions without a selection in the tree

- Run SQL query no longer fails with "selectedNode is null" when nothing is selected in the tree: the query tab opens
  on the database the connection uses (else the first database of the profile). The Run SQL query button is always
  enabled.
- Actions that need a database, schema, table or column (create, edit or drop a table, indexes, add, edit or drop a
  column, table maintenance, open in the designer, ...) say "Select a table in the tree first." instead of failing.
  Reloading the tree clears the selection and disables the buttons that need one.

05-10-2026: Error handling, wording and small fixes

- Open designer on a server without a designer only says so and no longer opens the designer after an error; the
  message names the server type instead of always MySQL.
- Saving the driver properties closes the dialog instead of showing a "saved" popup.
- Dropping a database asks with the server's own word for it.
- The table data grid no longer adds a header listener on every page; the undo of the cell editor uses the menu key
  (Cmd on macOS), keeps one history per shown cell and no longer fails on read-only cells.
- Designer: File menu items have their own mnemonics (Open, Save, Save as, the exports and Close), Edit > Delete
  selected and the View items have one too. Menu and context menu items are in sentence case, a new note attached
  to an object reads "New comment" instead of "New Table", and the properties button has a proper tooltip.
- An image that cannot be loaded is noted in the log.

05-10-2026: Slow work off the event thread

- The query tab runs its statements in the background: the window stays responsive, the run buttons are disabled and
  the status bar says "Running..." until the statements are done.
- A new connection window opens at once and connects and lists its databases in the background.
- The splash and the scrolling credits run on the event thread; credits that cannot be read are noted in the log.

05-10-2026: Data safety fixes

- Cancel in "Save model as" no longer writes the file. When saving fails or is cancelled while closing the designer,
  starting a new model or opening another one, the designer stays open with the unsaved model. Model files are
  written as UTF-8.
- Emptying a cell in the table data writes NULL (it wrote an empty text, which failed on number columns). A NULL cell
  opens empty in the editor, so the text "null" can be typed as a value of its own.
- Saving a binary cell whose row can no longer be found reports an error and removes the empty file; a failed
  download removes the partial file too.
- The Update button of the cell editor only changes the grid when the database accepted the change.
- The length of a column must be a number or precision and scale; the values of ENUM and SET are written as quoted
  literals. A type name that is not a plain name and an unknown MySQL storage engine are refused.

05-10-2026: Connect dialog with a list of profiles

- Connect to server shows the saved profiles in a list at the left, with New, Remove and Duplicate buttons above it.
  This replaces the Profile drop-down and the Delete and Duplicate buttons next to Save and Connect.
- The name of a profile is a field of its own and can be changed; Save renames the profile.
- Selecting another profile with unsaved changes asks to save or discard them. New makes an unsaved "New profile",
  Duplicate saves "<name> copy". An empty list shows a hint.
- Test connection and its result are at the bottom left of the dialog; a long error is cut off and shown in full
  as a tooltip. The dialog can be resized.

05-10-2026: Choose the databases and schemas of a profile

- Connect to server has two tabs. "Connection" holds the server settings; "Databases and schemas" opens after a
  successful Test connection and shows a tree with checkboxes of the databases of the server (on PostgreSQL each
  database opens to its schemas, loaded when you open it). This replaces the free text Databases field.
- Nothing ticked shows everything. A ticked database without ticked schemas shows all its schemas, ticking a schema
  ticks its database, unticking a database forgets its schemas. The first ticked database is the one connected to.
- Changing host, port, user, password or server type disables the tab until you test again; the ticks are kept.
  A ticked database that no longer exists is dropped when you save.
- The selection filters the tree, the export and import trees, the query tab schema picker and the user manager.
  Exporting a whole database still includes unticked schemas, the export window says so. The table count in the
  database properties counts the shown schemas.
- profiles.xml keeps <databases> and adds an optional <schemas> element; older files load unchanged.
- Mnemonics of Server type, Test connection and Duplicate no longer clash with Username and each other.

05-10-2026: Spacing in dialogs, length of integer columns, pending state in Generate

- Connect to server, Upload and Download no longer have empty space above the buttons: the filler row of a form
  takes no height and the error line only shows while there is a message.
- Table editor: an existing column shows a length only for types that take one (varchar, decimal, ...), integer
  columns no longer show "10".
- Generate (designer): the checks show a dash until they have run, then done or failed.

05-10-2026: Dialog layout fixes found on screen

- The application starts again: the Tools menu items were enabled before the window list existed.
- Table editor: the form scrolls when the window is too small instead of squeezing the column list away, the SQL
  preview is four lines high and the read-only schema field no longer takes the focus.
- Edit field: the type of an existing PostgreSQL column is selected (int4 shows as integer) and Unsigned is only
  checked for types that have it.
- Properties windows of a table and a database have a minimum width.
- Screenshots in docs/ retaken.

05-10-2026: SQL preview, process list controls, preferences, designer validation

- Table editor: "Show SQL" shows the statements that Save runs (the CREATE TABLE of a new table, the changes of an
  existing one) and keeps them up to date while you type. Columns have a comment (MySQL and PostgreSQL) in the table
  editor and in the field dialog of the tree; the comment of existing columns is read from the server.
- Process list: Pause and resume, Hide idle, a refresh interval of 1, 2, 5 or 10 seconds, and double click (or Show
  query) opens the full statement in a read-only editor with SQL colouring and a Copy button.
- Settings > Preferences: editor font size (applies at once to the query editor, the output panel and the other SQL
  editors), the default folder of the export, import, upload and download windows, and the default file encoding of
  the export and import windows. The settings file is written with proper XML escaping.
- Designer: the properties of the model, a database and a table refuse an empty name, a database name that another
  database of the model has, and a table name that another table in the same database has. The author of a model can
  be edited at any time.

05-10-2026: Create database options, schema management, rename and duplicate table

- Create database: the dialog checks the name against the databases in the tree and offers the options of the server,
  taken from the server itself: character set and collation on MySQL (the collations follow the chosen character set),
  owner and encoding on PostgreSQL.
- Schemas (PostgreSQL): the context menu of a database now creates and reloads schemas, and the menu of a schema renames
  and drops them (drop asks for confirmation); these menu items did nothing before.
- Tables: Rename table and Duplicate table (structure, optionally with the rows; auto numbering of the copy continues
  after the copied rows) in the context menu of a table.
- Properties (context menu of a table and of a database): a read-only summary. A table shows name, database, schema,
  engine or type, comment, rows, columns and size; a database shows its character set and collation (MySQL) or owner and
  encoding (PostgreSQL) and the number of tables.

05-10-2026: Cancel for jobs, export and import options

- Export, import and the upload and download of a binary cell can be cancelled. The progress window has a Cancel
  button that becomes Close at the end (closing the window or Esc cancels as well) and a status line with what it is
  doing ("Exporting shop.orders", "120 statement(s) done"). A cancelled export deletes the partial file, a cancelled
  import reports how many statements ran and whether they were rolled back, a cancelled download removes the partial
  file. The upload and download windows have a working Cancel while the transfer runs.
- Export options: DROP ... IF EXISTS and CREATE ... IF NOT EXISTS, the file encoding (UTF-8, UTF-16, ISO-8859-1,
  windows-1252, US-ASCII), several rows per INSERT, the views of a database or schema (structure), wrapping the script
  in a transaction, and disabling foreign key checks (MySQL only, PostgreSQL needs superuser rights for that). A file
  name ending in .gz is gzip compressed. The defaults give the same script as before. MySQL views are no longer
  exported as tables.
- Import options: stop on the first error or continue and list the failed statements, run in a single transaction
  (rolled back on an error or cancel), the file encoding, .gz files, and the statement count in the progress window.
  An error now names the statement that failed.

05-10-2026: Test connection, duplicate profile and optional saved password

- Connection profile: "Test connection" connects with the values in the form (not the saved profile) on a background
  thread and shows "Connected to <server> <version>" in green or the error in red inside the dialog, then closes the
  connection again. "Duplicate" saves a copy of the selected profile as "<name> copy". "Save password" (on by default,
  profiles written before keep their password): when off, the password is not written to profiles.xml and is asked for
  when connecting.

05-10-2026: Clearer layouts for the field, table, index and user dialogs

- Designer table properties: the fields tab has the list of fields on the left (Add, Duplicate, Remove with
  confirmation, Up, Down) and one form for the selected field: name, type, length, default, comment, the constraints
  (Primary Key, Not null, Unique, Auto Increment, Index) and, for servers whose types have them, the type options
  (Unsigned, Binary, Zerofill). The length must be a number (or precision and scale such as 10,2; ENUM and SET list
  values), field names must be unique, and OK reports the problem inside the dialog. The comment of the table is
  written to the database, the notes only stay in the model file.
- Table editor: database (and schema), name, type and comment in one column, the columns in a grid that is edited in
  place (name, type, length, not null, primary key, auto increment, default) with the details in a group "Column:
  <name>", new columns are called column_1, column_2, ..., Ctrl/Cmd+S saves and a missing name or column is explained
  below the form.
- Indexes: a list of all indexes with their type on the left, the editor on the right, the type as Normal, Unique or
  Fulltext, and Close instead of Cancel.
- Connection profile: "Databases:" with the explanation as a hint under the field. Foreign key dialog: Remove pair is
  disabled for the last pair and hints explain the server default and a key to the table itself. User manager: search
  field, privileges in groups (Data, Structure, Administration) with Select all and Select none, a mark and a question
  before unapplied changes are discarded, one error message, and Drop for accounts. About shows the version, commit,
  Java version and licence notice, with a Credits button.

05-10-2026: Modernisation (Maven, Java 25, PostgreSQL support)

- Dialogs share one base (ui.util.FormDialog): the action button is labelled with the action (Create, Save, Export,
  Import, Connect), Enter is the default button, Esc cancels, the first field has the focus and a validator shows its
  message in red inside the dialog, so typed data is kept. Create database, New index, Add user (name checked, password
  twice) and Change password use it, as do the foreign key, driver, preferences, connection profile, field, designer
  properties, upload and download dialogs. Labels end with a colon and have mnemonics (Alt+letter), titles are in
  sentence case. Export and Import are resizable and named "Export data" and "Import data": Export groups its options
  (Content, Statements), has Select all and Clear for the tree, and both have an editable file field; Import shows its
  target. The progress window names the operation and target, shows a percentage and keeps a Close button for when the
  job is done.
- Dialog fixes from an audit: Export validates the selection, the options and an existing file before it starts, and
  Import checks the file and names its target; both open directly (the format step with only SQL is gone). Cancel in
  the designer's property dialog discards field edits; the Generate dialog checks and generates on a virtual thread and
  lists the problems in the dialog. The driver, profile, process list, field, index, upload and download dialogs
  validate their input, confirm destructive actions and keep the window usable while they work. Import, Export and
  Designer are disabled in the Tools menu while no connection is open. The "Not null" option means the same in the
  column editor and the table editor (an existing column was shown inverted).
- Distribution: Maven profiles `jlink` (runtime image with only the needed JDK modules, 59 MB) and `package`
  (jpackage: eSQLManager.app 89 MB, `-Djpackage.type=dmg` 71 MB), scripts in src/package. The packaged application
  keeps conf/ and credits.txt in ~/.esqlmanager (app.DataDirectory, seeded from the bundled runtime/); started from
  runtime/ nothing changes.
- Designer as an internal frame: the model designer (designer.ui.DBCreator) is a JInternalFrame on the desktop of
  the main window, with its own menu bar, toolbar and frame icon, one per model. The window selector of the toolbar
  lists designers next to the connection windows. Closing it asks to save the model; disconnecting closes the
  designers of that connection first (ESQLManagerUI.closeDesigners). When the main window gets smaller, a frame
  that is not maximized is moved and shrunk to stay inside the desktop (DesktopUtils.keepFramesInside).
- Selected tabs stand out: a darker background and the accent underline, also when the focus is elsewhere
  (TabbedPane defaults in settings.Appearance). A tab that is opened is put in front.
- Status bar per tab: the message below the tabs of a connection window belongs to the tab it is about and is shown
  while that tab is in front: a loaded table or table list on the table view tab, a query's outcome on its query
  tab. A tab without a message of its own (Help, a new query or editor tab) leaves the bar empty. Tree actions
  (schemas listed, opened in the designer) go to the output panel.
- PostgreSQL schemas in export, import and the query tab: the export and import windows show the schemas of a
  database and open at the node selected in the tree; exporting a database takes every schema, the script names
  schema.table and creates missing schemas (Dialect.createSchemaIfMissingSql); importing into a schema (also in
  the schema's context menu) runs unqualified names there and restores the previous schema afterwards. The query
  tab has a schema picker next to the database (Dialect.useSchemaSql sets the search_path, the completion
  follows it). Contract tests exportOfADatabaseRestoresEverySchema and importIntoASchemaPutsUnqualifiedTablesThere.
- Designer layout: tables keep their model order within a layer, so the shop model has customers above products and
  the foreign key lines no longer cross.
- Connection window and designer toolbars: 20px icons and 32x30 buttons, the same as the application toolbar (ui.util.ToolbarButtons).
- PostgreSQL schemas: the tree is server > databases > schemas > tables (MySQL keeps databases > tables). A
  schema node has Reload tables, Create table, Open in designer, Export and Drop schema, a database has Create
  schema and Reload schemas; menu words come from the dialect. Every statement on a table names schema.table, the
  query completion knows the tables of all schemas (schema. lists the tables of a schema).
- Logo: a new vector logo (database with an "e", icons/logo.svg) is the window icon at 16 to 512px and the
  Dock icon on macOS, replacing the 16x16 GIF. The MySQL and SQL Server icons are heavier, brand icons are
  lighter on a dark theme and white on a selected row.
- Server icons: the profile lists, the connection window and the server node of the tree show the logo of the
  server (PostgreSQL, MySQL, Oracle, SQL Server; Devicon and Simple Icons, 18px), lighter on a dark theme;
  the window selector in the toolbar shows it too.
- SQL query: every statement that returns rows gets its own closable result tab, named after the statement with the
  full text as tooltip, and a line with the time it ran, the database, the rows and the duration (at most 20 tabs).
- Help tab: dark pages in a dark theme, white pages in a light theme.
- Documentation: README with a features table per server (SQL Server create and drop database not verified) and the
  known gaps, screenshots of the connection window, the designer and the query tab, in the light appearance only.
- Layout fixes after looking at every screen in light and dark: Settings only has the appearance (the auto-update
  fields and their settings.xml entries are gone), the user manager has padding and a Granted group, the process list
  opens wide enough for its columns and stops refreshing when it closes, the foreign key dialog centres its labels,
  the Add field button lines up with the buttons below it, grid lines and tree and desktop backgrounds follow the
  theme, "separated" is spelled correctly.
- Dialogs: settings, connection profile, driver, field properties, import, export, upload and download, progress and the
  designer property and generate dialogs use layout managers instead of absolute positions, with padding and the buttons
  at the bottom right.
- Process list: ProcesslistCC holds the connection, the refresh thread and the kill action, the window only shows the list.
  The database tree keeps one tree model and only shows what its controller loads.
- Create table, Edit table and Indexes open as closable tabs of the connection window ("New table", "Edit orders",
  "Indexes orders"), one per table, with Save and Cancel at the bottom; closing with unsaved changes asks first.
  The screens use layout managers instead of absolute positions.
- Toolbars and menu bar are compact, the paging buttons of the table data sit in the centre of the status bar below
  the tabs, with the message of the tab in front on the left.
- Help: the user documentation is Markdown in docs/ (shown by GitHub and rendered in the help tab with commonmark),
  links between pages stay in the help tab, web links open in the browser. The old HTML help pages are gone.
- Designer context menus: the empty canvas adds a database, table or note at the click point, selects all, arranges,
  toggles the grid and opens the model properties. Tables, databases and notes have their own menus (properties,
  foreign key, link to a database, add a table or note, remove a link, delete), right click selects the object.
- Context menus of the database tree are built per node and only show what the server supports (no MySQL, Postgres
  or SQL Server submenus). New: Open, New query, Users, Export, Import, Indexes and Reload in the menus where they
  apply; Check and Repair only on MySQL. Right click (ctrl-click on macOS) selects the node under the cursor first.
- Dialogs: one helper for all message boxes. Errors show the error icon, dropping and deleting asks with a warning
  that names the object and a button named after the action, revoking privileges asks first. Clearer texts and titles
  (Upload no longer says Download, Drop user, typos), no popups after adding or saving a profile.
- Connection windows have a flat, taller title bar in the colours of the theme, with the server icon and Lucide buttons
  for minimize, maximize, restore and close. Split pane dividers are thin and flat, without one-touch arrows.
- SQL query: opens as a tab of the connection window instead of a separate window (several tabs, "Query 2", ...), with a result tab
  per statement below the editor. Open and save .sql files.
- SQL query: "Run selection" runs the selected text or the statement at the caret (Cmd/Ctrl+Enter), "Run all" every statement in
  order (Cmd/Ctrl+Shift+Enter). Statements are split on ; outside strings, quoted names, dollar quotes and comments. The outcome of
  each statement is logged, the status bar shows the total time or which statement failed; running stops at the first error.
- SQL query: auto completion (Ctrl+Space, Cmd+Space, Cmd/Ctrl+Shift+Space, and after a period) of keywords, functions, the tables of
  the database and their columns; aliases are resolved, names that need quotes are inserted quoted.
- Connection window: the Create database and Drop database toolbar buttons are gone, the context menus of the tree still have them.
- Disconnect asks "Disconnect from <connection>?" with the buttons Disconnect and Cancel.
- Database tree: selecting a database or table no longer opens a tab; a double click does, and the tab comes to the front with focus.
- Dialogs: Esc closes them, the same as the close button.
- Connect dialog: has a Close button. The status bar shows a green light and "Connected" while a connection is open and a red light and
  "No connection" otherwise, instead of "Ready...".
- Status bar: the status light is in front of the message ("Ready..."), the server and account of the active connection are on the right.
  Each connection window has its own status bar below the tabs with the message of the tab in front, with the paging buttons of the
  table data in the same bar.
- Connection profiles: the default profiles are PostgreSQL (port 5432, user postgres, no password stored, selected at start) and MySQL on localhost;
  the SQL Server profile is gone.
- start.sh: the sample PostgreSQL container uses the first free port from 5432, so it does not clash with another PostgreSQL on the machine.
- Version: the title bar and splash show the version from the pom and the commit hash of the build (with -dirty for uncommitted changes) instead of a
  build number.
- Designer reverse engineering: "Open in designer" on a database reads its tables, columns, primary keys and
  foreign keys (composite keys too, views left out) into a model that can be saved and generated again.
- Designer layout: tables are placed automatically with the Eclipse Layout Kernel (layered, referenced tables first,
  tables without relations in a grid below), also for any model with View > Arrange Automatically.
- Package structure by feature: dialect (with mysql, postgres, sqlserver and oracle sub packages), jdbc, error, job,
  export, importer, server, settings, and shared ui split into icon, table, editor and util. The designer UI is split
  into diagram and dialog. The old domain, data and importexport packages are gone.
- Designer export: File > Export as PlantUML... and Export as Mermaid... write the model as an ER diagram.
- Designer foreign keys: drag from the field icon of a column onto a column of another table, or use "Add Foreign Key..."
  in the table menu or the Foreign Keys tab of the table properties. The dialog supports several column pairs, a name
  and the ON DELETE and ON UPDATE actions, and checks that the columns exist and their types fit. Double click a line to
  edit it, Delete removes it.
- Designer relations: foreign keys are drawn from column to column as orthogonal lines with rounded corners, a crow's
  foot at the many side and a bar at the one side. Clicking a line selects it, hovering highlights it.
- Designer look: tables are cards with a coloured header, an icon per field (key, link for foreign key columns), the type
  right aligned, a soft shadow and a hover row, in the colours of the light or dark theme. The database is a pill and a
  comment a note. The header shows the storage engine only on servers that have them (no more "(InnoDB)" on PostgreSQL).
  A subtle dotted grid can be switched off in View > Show Grid.
- Query editor: RSyntaxTextArea replaces the home-made highlighter (SQL highlighting, line numbers, undo and redo), its colours
  follow the light and dark theme. The output panel uses the same SQL colouring as the editor, syntax.xml is gone.
- Designer foreign keys (backend): a model holds foreign keys between tables, saves them in model files of version 0.2
  (0.1 files still open) and Generate creates them after all tables exist. Model files are written with JDOM, so names
  with < & " no longer break them. The dialects add and drop foreign keys, on MySQL only for InnoDB tables.
- Output panel: log lines are shown exactly as written (the first line was indented one space less than the others), and the text colour
  follows the theme.
- Icons: the GIF icons (also the red and green status light) are replaced by vector icons from Lucide (ISC license, in resources/icons/svg). They scale sharply on high resolution
  screens and follow the colours of the light and dark theme.
- Appearance: the look and feel is a preference (Settings > Preferences): follow the system, light, dark or native. On macOS the Mac themes of
  FlatLaf are used, with the menu in the screen menu bar and the title bar following the system.
- Errors: one ErrorHandler logs an error once and shows one message, services and repositories no longer swallow exceptions.
- Java 25: records, pattern matching, switch expressions, text blocks, lambdas and virtual threads for background work. Resources are closed
  with try-with-resources (DatabaseConnection included), Observable is replaced by ProgressListener, the PRO/LE distinction is gone.
- ApplicationContext resolves the image loader, settings and the ConnectionContext of every open connection. A ConnectionContext wires the
  repositories and services of one connection once, controllers no longer create them.
- Code style: Spotless formats the sources (tabs, 160 columns, LF), .editorconfig added, the build checks the formatting.
- Architecture: packages per feature (table, database, importexport, blob, user, designer, query, connection, app), each with
  controller, service and repository layers. SQL only runs in repositories, which ask the Dialect. The domain classes are plain data.
- Documentation: README with a feature list per database and a screenshot, CLAUDE.md with the design decisions.
- Tests: JUnit and Testcontainers run the same scenarios against PostgreSQL 17 and MySQL 8.
- Removed: license and registration checks, the auto-updater and its dialog, the dynamic class loader, old unused
  files and commented out code.
- Cleaned up: resources are closed with try-with-resources, deprecated API calls replaced.
- Generated SQL: values are escaped per database and names are quoted by the dialect. The WHERE clause that finds a
  row for editing, deleting and uploading is built in one place. An empty cell is stored as NULL, not as the text "null".
- Paging orders by the primary key, so rows no longer move after an update on PostgreSQL.
- Status bar shows the server, the account and the last action (rows loaded, time taken) instead of a copyright text.
- User manager rebuilt: a UserAdmin per dialect and a new window. It works on MySQL 8, which the old one did not
  (it wrote into the mysql.user table).
- PostgreSQL support with the right defaults (port 5432, user postgres). All features work on PostgreSQL and MySQL:
  create/modify/drop tables, columns and indexes, import and export as SQL, database designer, user manager
  (roles and privileges), process list, server status and variables, table maintenance (VACUUM, ANALYZE).
- Export/import: one code path, UTF-8, NULL values, auto numbering continues after an import on PostgreSQL.
- Look and feel: FlatLaf instead of the native macOS look, which made resizing very slow. Resizing the window and the
  output panel is fast, the output panel scales with its panel, has a vertical scrollbar and no longer wraps lines.
- Data grids show subtle grid lines and size their columns to the content.
- Logging with Log4j 2 instead of System.out, with connection details and queries in the output panel.
- Dialect layer: everything that differs per database (quoting, literals, DDL, paging, switching database,
  maintenance, export, process list, status, users) is decided by a Dialect. Callers no longer check the server type.
  The dialect only writes SQL and reads result rows, the repositories are the only code that runs statements.
- Runtime files (conf, credits) are grouped in runtime/, passwords are no longer part of the committed profiles.
- Packages: merged esql and nl.errorsoft into nl.errorsoft.esql, the database designer lives under it as dbcreator.
- Build: Maven with the Maven wrapper, standard src/main/java and src/main/resources layout, Java 25, UTF-8 sources.
  The old dist and lib folders are gone, JDBC drivers (MySQL, PostgreSQL, SQL Server, Oracle) come from Maven Central.
